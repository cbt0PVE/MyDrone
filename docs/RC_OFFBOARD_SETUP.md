# RC 开关 + Offboard 共存设置手册

> 目标：遥控器平时兜底，**拨开关才放行代码控制**，飞手随时打杆或切回抢回。
> 全程**拆桨**。上桨要等第 6 节全部通过。

---

## 0. 先理解为什么以前必须关掉遥控器

PX4 的解锁是"预检制"，不是"命令制"。它会在 Arm 之前逐条检查，任何一条不过就拒绝，而 `RC` 相关的检查有三层：

```
第一层：RC 链路本身     没信号 → RC Link Lost → 预检直接失败，arm 被拒
第二层：RC 校准状态     没校准过 → 预检失败
第三层：RC 抢权         检测到打杆 → 退出自主模式
```

你以前把 RC 整个关掉，等于把三层一起拆了，所以能解锁。现在要做的不是拆掉它，而是**让三层都健康**：信号不断、校准过、抢权阈值不误触发。

关键认知：**Offboard 和 RC 不是互斥的**。PX4 里 Offboard 只是"模式之一"，遥控器始终是最高优先级的物理输入。

---

## 1. 五分钟准备

| 检查 | 说明 |
| --- | --- |
| 拆桨 | 必须。下面有大量"切换模式/解锁"操作 |
| 遥控器开机对频 | 全程开机，不要中途关 |
| 摇杆回中、油门最低 | 上电瞬间的姿态会成为某些模式的基准 |
| 安全开关 | Pixhawk 4 上电后要长按安全开关到常亮，否则电机不会转。这一步漏了会误判成"解锁失败" |
| QGC 连接 | USB 直连最稳（`serial://COMx`），数传也行 |

## 2. 第 1 步：Radio 校准 + 通道清点

**QGC → Vehicle Setup → Radio → Calibrate**

1. 按提示把两个摇杆推到四角、油门推到底。
2. 提示"拨动所有开关"时，把 6 个开关**每个都拨到两端各一次**（三段开关拨到底再拨到顶）。
3. 完成后退回 Radio 页，下面是 **Channel Monitor**。

**现在开始记录。** 表格填进 `docs/PX4_PARAMS.md`：

| 通道 | 对应开关/摇杆 | 类型（两段/三段/摇杆） | 低值 | 中值 | 高值 |
| --- | --- | --- | --- | --- | --- |
| CH1 | 横滚 | 摇杆 | 1000 | 1500 | 2000 |
| CH2 | 俯仰 | 摇杆 | 1000 | 1500 | 2000 |
| CH3 | 油门 | 摇杆 | 1000 | — | 2000 |
| CH4 | 偏航 | 摇杆 | 1000 | 1500 | 2000 |
| CH5 | ? | | | | |
| CH6 | ? | | | | |
| CH7 | ? | | | | |
| CH8 | ? | | | | |

判断方法：**只有 1000/2000 两个值的是两段，有 1000/1500/2000 三个值的是三段。**

### ⚠️ PPM 的隐藏限制

PPM 通常**最多 8 个通道**。你有 6 个开关 + 4 个摇杆通道，如果接收机按 10 通道输出，多出来的会直接被截断。

**症状**：QGC 里某个开关怎么拨都没反应，通道 Monitor 里根本没有那一行，或者始终卡在 1500。

**处置**：优先把关键功能（模式开关、Offboard 开关）放在 CH5/CH6/CH7；实在不够用，考虑换 SBUS（Pixhawk 4 的 RC IN 也支持 SBUS，一根线的事，通道数直接到 16）。这个决定明天最好一次性做掉。

### 顺带看一眼抖动

静置 10 秒，看摇杆通道的数值。**稳定在 1500 不动**是正常；在 1496–1504 之间微跳正常；如果跳动超过 ±30（即 3%），说明 PPM 信号本身有问题（线太长、干扰、接收机供电不足），调死区治不了。

## 3. 第 2 步：绑定模式开关（Flight Modes）

**QGC → Vehicle Setup → Flight Modes**

- `Mode Channel` 选**开关 A** 所在通道（比如 CH5）。
- 三个档位分别绑定：**Position（定点）/ Altitude（定高）/ Stabilized（自稳）**。
  - 建议档位顺序按"由安全到激进"或按你习惯，但**至少保留一个手动模式**，那是最后的救命档。
- 保存后，在 QGC 顶部模式显示处拨开关验证：档位变化时模式名要跟着变。

> 这一步只涉及人工飞行，跟代码无关。先把这块做扎实，后面才有的退。

---

## 4. 第 3 步：绑定 Offboard 开关

**QGC → Vehicle Setup → Parameters**，搜索 `RC_MAP_OFFB_SW`。

- 默认 `0` = 禁用。
- 改成**开关 B 的通道号**（比如 `7`）。
- 改完**重启飞控**（有些参数需要重启才生效）。

行为：
- 开关 B 拨到"允许位" → PX4 尝试切 `OFFBOARD`；
- 拨回"常规位" → 退出 Offboard，回到模式开关 A 指定的模式。

**重要前提**：切 Offboard 时**必须已经有 setpoint 流在跑**。空着切，PX4 会拒绝或切进去立刻掉出来。所以验证顺序永远是：先跑脚本发流 → 再拨开关。

> 如果 `RC_MAP_OFFB_SW` 在你这个固件版本里搜不到，说明版本太老，用 `COM_RC_OVERRIDE` + 模式开关里直接绑 OFFBOARD 的替代方案，告诉我再定。

## 5. 第 4 步：参数表（逐条改，逐条记）

| 参数 | 建议值 | 为什么 | 改前 | 改后 |
| --- | --- | --- | --- | --- |
| `RC_MAP_OFFB_SW` | 开关 B 通道号 | Offboard 使能开关 | 0 | |
| `COM_RC_IN_MODE` | `0`（RC 输入） | 之前"关遥控器"很可能改的就是它，必须改回来 | ？ | |
| `COM_RC_OVERRIDE` | 见下 | 打杆抢权 | ？ | |
| `NAV_RCL_ACT` | `Land` 或 `Hold` | RC 丢失后的动作。**室内绝对不要 Return** | ？ | |
| `COM_RC_LOSS_T` | `1.0` | PPM 容易瞬断，0.5s 太敏感；但别超过 2s | ? | |
| `COM_OF_LOSS_T` | `1.0` | Offboard 流中断多久算丢失 | ? | |
| `COM_OBL_RC_ACT` | Position / Hold | Offboard 中 RC 丢了的动作 | ? | |
| `RC_STICK_DZ` | 先不动 | 默认通常已是 0.1，调大收益很小 | ? | |

### `COM_RC_OVERRIDE` 怎么看

点开参数看**描述文本**，分两种情况：

- 描述是「0 禁用 / 1 启用」→ 设 **`1`**。
- 描述是位掩码（0/1/2/3，bit0=AUTO、bit1=OFFBOARD）→ 设 **`3`**。**这是最容易被漏的**：只设 1 的话，你在 Offboard 里打杆可能根本抢不回来，而你以为自己能救机。

参数表里如果还有 `COM_RC_STICK_OV`（打杆阈值，常见默认 30%），**别为了"小杆量也能抢权"去调小**。阈值存在的意义是过滤手抖，调小了等于回到你最初的问题。

## 6. 第 5 步：验证清单（拆桨，按顺序）

每项都要看到**预期现象**才算过。不过就停在原地排查，别往下走。

| # | 操作 | 预期现象 | 不过怎么办 |
| --- | --- | --- | --- |
| 1 | 拨开关 A 三档 | QGC 模式名跟着变（Stabilized/Altitude/Position） | 回第 3 步，检查通道号 |
| 2 | 跑一个只发 setpoint 的脚本（不解锁） | 脚本不报错，飞控持续收流 | 检查端口/波特率 |
| 3 | 开关 B 拨到允许位 | QGC 模式变 **OFFBOARD** | 见下方排查表 |
| 4 | 开关 B 拨回 | 模式回到开关 A 的档位 | 同上 |
| 5 | 在 Offboard 下发流状态下打杆 | 模式自动退出 Offboard，回到 Position/Altitude | `COM_RC_OVERRIDE` 位掩码没覆盖 Offboard |
| 6 | 拔掉接收机电源（模拟 RC 丢失） | 按 `NAV_RCL_ACT` 动作（落地/悬停） | 检查 `COM_RC_LOSS_T` 是否太短 |
| 7 | 发 arm 指令 | 解锁成功，QGC 显示 Armed | 看 QGC 顶部红色预检提示 |
| 8 | armed 状态下拨开关 B | 能切进/切出 Offboard | 回第 3 步 |

### 第 3 项不过的排查顺序

1. **脚本在发流吗？** 先确认，这是最常见的。
2. `RC_MAP_OFFB_SW` 是不是改完没重启？
3. 通道号对不对？在 Channel Monitor 里盯着拨，看数值真的到 2000 了吗？
4. 是不是被模式开关 A 的档位覆盖了？把 A 拨到 Position 再试。
5. QGC 顶部红色条写了什么？**先读它**，比猜快十倍。

## 7. 第 6 步：代码这边的配合（顺序错了全白搭）

PX4 的规矩：**先有心跳，再切模式，最后解锁**。

```
1. 持续发 setpoint（≥2Hz，建议 10Hz）      ← 先跑起来，别停
2. 等 1~2 秒，让飞控确认流稳定
3. 拨开关 B 到允许位（或脚本调 offboard.start()）
4. arm 解锁
5. 执行任务
```

对应到你现有的 `takeoff.py`：它现在是 `arm()` → `set_attitude()` → `offboard.start()`，**顺序反了**。明天如果时间紧，最小改动是把 `arm()` 挪到 `offboard.start()` 之后；如果来不及改，那就靠手动拨开关 B 来切模式，脚本只负责发流和解锁。

还有一个坑：`takeoff.py` 的 `finally` 里有 `action.kill()`。**明天测试时把它注释掉**，换成 `land()`。否则任何一次异常（包括你按 Ctrl+C）都是直接断桨。

## 8. 明天的建议时间线

| 时段 | 事 |
| --- | --- |
| 前 30 分钟 | 拆桨、上电、Radio 校准、通道表填完（第 2 节） |
| 30–50 分钟 | 模式开关 A 绑好并验证（第 3 节） |
| 50–70 分钟 | 参数改完 + 重启 + 记录表填完（第 4/5 节） |
| 70–120 分钟 | 验证 1–8 项，尤其是第 5 项（打杆抢权） |
| 之后 | 上桨、系留、低高度悬停 |

**如果 120 分钟还没过第 5 项**，不要上桨。打杆抢权不过，等于飞手没有接管能力，这是红线。

---

## 9. 一句话备忘

> 遥控器不是要关掉的东西，是要**校准好、绑好开关、设好抢权**的东西。
> 顺序永远是：**先发流 → 再切模式 → 最后解锁**。
