# 项目上下文

## 1. 平台

- **机型**：250 级穿越机（FPV 竞速机架），机内空间极小，4S/6S 锂电。
- **飞控**：Holybro Pixhawk 4（FMUv5），PX4 固件。
- **遥控链路**：接收机接飞控 **`PPM RC`** 口，模拟脉冲信号；6 个开关（两段/三段）。
- **数链**：MAVLink。当前 USB/数传连 PC；后续香橙派机载电脑走串口直连。
- **控制栈**：MAVSDK (Python)，Offboard 模式发 NED 速度/位置 setpoint。

## 2. 外设规划

| 设备 | 型号 | 用途 | 接口/供电 |
| --- | --- | --- | --- |
| 激光定高 | 北醒 TFmini-S（0.1–12 m 单点 ToF） | 室内垂直厘米级定高，替代气压计 | UART，飞控 5V 串口供电 |
| 机载电脑 | 香橙派 5 Pro（RK3588S，8G/16G） | 6 TOPS NPU（RKNN）跑轻量 YOLO / 目标追踪 | 航模 UBEC 5V 5A（宽压 ≥26V 输入） |
| 视觉模型 | YOLOv8n + ByteTrack | 人员检测跟踪 | PC 端已验证（RTX 4060） |

## 3. 核心痛点与根因

**现象**：必须在飞控参数/QGC 里禁用遥控器，Python 才能 Arm 并进 Offboard；开着遥控器就控不了。

**根因（两条）**：

1. **RC 失效保护锁死解锁**：遥控器关机时 PPM 口无脉冲/乱码 → PX4 判 RC Link Lost / Manual Control Lost → 安全预检硬性禁止 Arm。
2. **RC 抢权与模式冲突**：遥控器开机时 PPM 存在电位器零点抖动，叠加默认 `COM_RC_OVERRIDE`（打杆抢权），飞控把微小抖动误判为飞手介入，踢出 Offboard；或模式开关通道与地面站模式广播持续冲突。

> 之前"禁用遥控器权限"很可能改的是 `COM_RC_IN_MODE`（No RC Checks）。恢复时务必把它改回 RC 输入模式，否则会掩盖问题而不是解决。

## 4. 目标方案

**遥控器与代码无缝共存**：

- 开关 A（三段）→ QGC **Flight Modes** 绑定，作人工飞行基础模式（Manual/自稳、Altitude/定高、Position/定点）。
- 开关 B（两段或三段）→ 参数 **`RC_MAP_OFFB_SW`** 绑定其通道号：
  - 允许位：放行 MAVSDK 的 Offboard 控制权；
  - 常规位：强制掐断代码控制，人工立刻接管。
- 飞手任意时刻打杆（`COM_RC_OVERRIDE`）即可抢回。

## 5. 标准操作流

**上电**：遥控器全程开机对频 → 摇杆回中 → 飞控上电 → 地面站连入。

**MAVSDK**：
1. 开关 B 拨到允许 Offboard 位；
2. 脚本以 ≥2Hz 持续发 setpoint（先发再 start，别反过来）；
3. 切 Offboard（`offboard.start()`）；
4. Arm；
5. 执行任务。

顺序要点：**先有心跳再切模式，先切模式再解锁**。反过来在 RC 参与时极易被预检拒绝。

## 6. 通道映射方法（当前进行中）

QGC → **Radio** 页 → 逐个拨动实体开关 → 看 `Channel 5`、`Channel 6`… 的数值条在 `1000 / 1500 / 2000` 间跳变 → 记录"哪个开关 = 哪个通道"。三段开关是 1000/1500/2000 三档，两段是 1000/2000 两档，可据此区分。
